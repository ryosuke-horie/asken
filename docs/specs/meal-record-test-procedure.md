## 1. 入力フェーズ

### 1.1 画像入力

| # | 手順 | 期待結果 |
|:---|:---|:---|
| 1-1-1 | 食事画像（JPEG）を撮影し、meal_type=lunchで送信 | 200 OK、分析が開始される |
| 1-1-2 | 食事画像（PNG）を選択し、meal_type=breakfastで送信 | 200 OK、分析が開始される |
| 1-1-3 | HEIC形式の画像を送信 | 200 OK、分析が開始される |
| 1-1-4 | 10MBを超える画像を送信 | 413エラーまたはバリデーションエラー |
| 1-1-5 | 食事以外の画像（風景写真等）を送信 | 分析結果が返るが、食品が0件または不正確 |
| 1-1-6 | meal_typeを指定せずに送信 | 400 Bad Request |
| 1-1-7 | 無効なmeal_type（例: "brunch"）で送信 | 400 Bad Request |
| 1-1-8 | meal_dateを明示的に指定（例: "2025-01-15"）して送信 | 指定日付で記録が作成される |
| 1-1-9 | meal_dateを省略して送信 | 今日の日付で記録が作成される |

## 8. E2E統合シナリオ

### 8.1 画像入力の一連フロー

```
手順:
1. 食事画像を撮影（例: ラーメンと餃子の画像）
2. meal_type = "lunch" で分析を実行
3. 分析結果を確認
   - 2品（ラーメン、餃子）が検出される
   - estimated_amount が "{数値}{単位}" フォーマット（例: "1杯", "5個"）
   - 各品目に栄養素が含まれる
4. 保存ボタンが有効であることを確認
5. 保存を実行
6. 履歴一覧に表示されることを確認
7. 履歴詳細を開き、データが正しいことを確認
```

### 8.2 テキスト入力の一連フロー

```
手順:
1. "チキンカツ定食、味噌汁、サラダ" と入力
2. meal_type = "dinner" で分析を実行
3. 分析結果を確認
   - 3品が検出される
   - 各品目の名前と量が妥当
4. 保存ボタンが有効であることを確認
5. 保存を実行
6. 履歴一覧に表示されることを確認
```

### 8.3 編集後の保存フロー

```
手順:
1. テキスト入力で分析を実行
2. 結果表示で品目名を編集（例: "ラーメン" → "味噌ラーメン"）
3. 保存ボタンが有効であることを確認
4. 保存を実行
5. 履歴詳細を開き、変更が反映されていることを確認
6. 非同期再計算が実行された場合、栄養素が更新されていることを確認
```

### 8.4 品目追加・削除後の保存フロー

```
手順:
1. テキスト入力で2品を分析
2. 品目追加ボタンで3品目を追加
3. 3品目の名前と数量を入力
4. 保存ボタンが有効であることを確認
5. 保存を実行
6. 履歴詳細を開き、3品が正しく保存されていることを確認
7. 再度編集画面を開き、1品を削除
8. 保存ボタンが有効であることを確認
9. 保存を実行
10. 履歴詳細を開き、2品が正しく保存されていることを確認
```

### 8.5 バグ修正検証シナリオ（EDG-730対応）

このシナリオは、responseSchemaによるフォーマット保証とcanSaveバリデーション修正の検証を行う。

```
手順:
1. テキスト入力で "ラーメンと餃子とビール" を分析
2. 結果表示を確認:
   - 3品が検出される
   - 全品目の estimated_amount が "{数値}{単位}" フォーマット
   - 使用される単位が18種のサポート単位のいずれか
3. 保存ボタンが有効であることを確認（以前はここで無効になっていた）
4. 何も編集せずに保存を実行
5. 200 OK、正常に保存される
6. 画像入力でも同様のテストを実施
   - 食事画像で分析
   - 保存ボタンが有効
   - 保存が成功
```

## 補足: E2Eテスト自動化の方針

本手順書のテストケースをE2Eテストに変換する際の指針:

| 項目 | 方針 |
|:---|:---|
| APIテスト | Go `e2e/` パッケージでHTTPリクエストを送信して検証 |
| レート制限 | Gemini API呼び出しテスト間に `waitForGeminiRateLimit()` を挿入 |
| テストデータ | `e2e-test-user` UIDを使用 |
| テスト順序 | 作成 → 取得 → 編集 → 保存 → 削除 の順で依存関係を管理 |
| 栄養素の検証 | 妥当な範囲（例: カロリー > 0）で検証、厳密な値は不可 |
| 単位の検証 | `SupportedUnits` リストに含まれることを検証 |
| フォーマット検証 | `estimated_amount` が `{数値}{単位}` の正規表現にマッチすることを検証 |
