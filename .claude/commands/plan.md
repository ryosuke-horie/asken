# 計画コマンド

このコマンドはplannerエージェントを呼び出し、コードを書く前に包括的な実装計画を作成します。

## このコマンドの機能

1. 要件の再確認 - 構築するものを明確化
2. リスクの特定 - 潜在的な問題とブロッカーを表面化
3. ステップ計画の作成 - 実装をフェーズに分割
4. 確認を待機 - 続行する前にユーザーの承認を必須

## 使用タイミング

`/plan`を使用する場合:
- 新機能を開始する時
- 重要なアーキテクチャ変更を行う時
- 複雑なリファクタリングに取り組む時
- 複数のファイル/コンポーネントが影響を受ける時
- 要件が不明確または曖昧な時

## 動作方法

plannerエージェントは:

1. リクエストを分析し、要件を明確な言葉で再確認
2. 具体的で実行可能なステップでフェーズに分割
3. コンポーネント間の依存関係を特定
4. リスクと潜在的なブロッカーを評価
5. 複雑度を見積もり（High/Medium/Low）
6. 計画を提示し、明示的な確認を待機

## 使用例

```
User: /plan 食事画像から栄養素を計算する機能を追加したい

Agent (planner):
# 実装計画: 食事画像栄養素計算機能

## 要件の再確認
- 食事画像をアップロードして食品を自動判定
- 判定した食品のカロリーと栄養素を計算
- 結果を画面に表示

## 実装フェーズ

### フェーズ1: 画像アップロード機能
- ファイル選択/ドラッグ&ドロップUI作成
- 画像プレビュー表示
- ファイルサイズ/形式のバリデーション

### フェーズ2: Gemini API連携
- 画像をGemini APIに送信
- 食品名を抽出するプロンプト設計
- レスポンスのパース処理

### フェーズ3: 栄養素計算
- 食品データベースとの照合
- カロリー・栄養素の計算ロジック
- 結果の表示コンポーネント

### フェーズ4: エラーハンドリング
- API失敗時のフォールバック
- 食品が見つからない場合の処理
- ローディング状態の表示

## 依存関係
- Gemini CLI（環境設定が必要）
- PostgreSQL（食品データベース）

## リスク
- HIGH: Gemini APIのレスポンス精度
- MEDIUM: 食品データベースのカバレッジ
- LOW: 画像処理のパフォーマンス

## 見積もり複雑度: MEDIUM

確認待ち: この計画で進めますか？（yes/no/修正内容）
```

## 重要な注意事項

CRITICAL: plannerエージェントは、「yes」「proceed」などの明示的な確認を受けるまでコードを書きません。

変更を希望する場合は:
- 「修正: [変更内容]」
- 「別のアプローチで: [代替案]」
- 「フェーズ2を先にして」

## 他のコマンドとの連携

計画後:
- `/tdd`を使用してテスト駆動開発で実装
- `/build-fix`を使用してビルドエラーが発生した場合に修正
- `/code-review`を使用して完成した実装をレビュー
